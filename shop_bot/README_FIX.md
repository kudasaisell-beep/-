# КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: убран автоматический cancel после покупки

## Проблема
Бот автоматически вызывал `cancel_buy()` после `fast_buy()`, если:
- `check-account` вернул ошибку
- Данные аккаунта были пустыми (login/session == "N/A")
- `confirm_buy()` упал с ошибкой
- `purchase_account_tx()` не удался

**Последствия:** товар уже был в статусе `paid` (деньги списаны с LZT), но бот пытался отменить покупку. Отмена невозможна для `paid` — товар оставался у бота, но данные не выдавались пользователю. Пользователь оставался без товара, а его баланс в боте мог быть списан (или не списан — в зависимости от момента падения).

## Исправления

### 1. `lzt_api.py`
- Добавлен `get_item_secure_data(item_id)` — получение защищённых данных после покупки (paid)
- `cancel_buy()` оставлен как метод, но добавлено предупреждение: использовать ТОЛЬКО для статуса `reserved`

### 2. `handlers/buy.py`
- **`_do_buy()`** (единичная покупка):
  - Убран `cancel_buy()` при любых ошибках после `fast_buy()`
  - После `fast_buy()` → сразу `get_item_secure_data()`
  - Если данные получены → списываем баланс (`purchase_account_tx`) → выдаём пользователю
  - Если данные НЕ получены → НЕ списываем баланс, НЕ делаем cancel, сообщаем админу для ручной выдачи
  - Убран `confirm_buy()` из критического пути

- **`buy_lzt()`** (оптовая покупка):
  - Аналогично: убран `cancel_buy()` из цикла
  - При ошибке получения данных — логируем, сообщаем админу, переходим к следующему лоту

### 3. `handlers/cart.py`
- **`checkout()`** (заказ из корзины):
  - Убран `cancel_buy()` и `confirm_buy()`
  - После `fast_buy()` → `get_item_secure_data()`
  - Данные получены → `purchase_account_tx` → release lock
  - Данные не получены → failed++, сообщаем админу, release lock

## Новый поток покупки
```
fast_buy(item_id) → OK?
  └─ NO: release lock, сообщение пользователю
  └─ YES: get_item_secure_data(item_id)
      └─ NO: release lock, НЕ списываем баланс, сообщаем админу
      └─ YES: purchase_account_tx() → списание баланса + запись в БД
          └─ NO: release lock, сообщаем админу (товар куплен, но не записан)
          └─ YES: выдаём данные пользователю, release lock
```

## Что делать, если уже есть "потерянные" покупки
1. Найдите `item_id` в логах бота или в истории покупок на LZT
2. Вручную выдайте данные пользователям через поддержку
3. Проверьте баланс пользователей — если `purchase_account_tx` не сработал, деньги на месте
4. Если `purchase_account_tx` сработал, но данные не выданы — пользователь заплатил, но не получил товар. Верните деньги или выдайте данные вручную.

## Установка
Замените файлы в проекте:
```bash
cp shop_bot/lzt_api.py /opt/shop/lzt_api.py
cp shop_bot/handlers/buy.py /opt/shop/handlers/buy.py
cp shop_bot/handlers/cart.py /opt/shop/handlers/cart.py
```
Перезапустите бота: `docker-compose restart bot`
